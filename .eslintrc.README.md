# ESLint Configuration

## Overview

This project uses ESLint for code linting with TypeScript support. The configuration uses the application and test TypeScript projects so that type-aware linting follows the same file scopes as type checking.

## Configuration Files

### `.eslintrc.cjs`
Main ESLint configuration file that specifies:
- Parser: `@typescript-eslint/parser`
- Project references: `./tsconfig.app.json` and `./tsconfig.test.json`
- Extends: Airbnb, Airbnb TypeScript, React, and React Hooks configurations
- Ignored patterns: `dist/`, `node_modules/`, `public/`

### TypeScript project configurations
The shared `tsconfig.json` contains compiler options. The scoped configurations extend it:
- `tsconfig.app.json` includes application source files and excludes tests.
- `tsconfig.test.json` includes application and test source files with test types.

### Why Separate TypeScript Configurations?

The shared `tsconfig.json` contains compiler options but does not define a file scope. Production and test type checking use `tsconfig.app.json` and `tsconfig.test.json` respectively.

ESLint uses both scoped projects for type-aware parsing. Test files are excluded from linting by `.eslintrc.cjs`, but remain covered by `tsconfig.test.json` for test type checking.

If a TypeScript file is not included in either project, ESLint will fail with:
```
Parsing error: ESLint was configured to run on [file] but that TSConfig does not include this file
```

## Usage

```bash
# Lint all files
npm run lint

# The lint script runs:
# eslint . --ext .ts,.tsx,.js,.jsx
```

## Files Linted

The ESLint configuration lints:
- All TypeScript files (`.ts`, `.tsx`) in `client/src/**/*`, `server/**/*`, and `shared/**/*`
- Test files (`.test.ts`, `.test.tsx`) are type-checked with `npm run check:test` but excluded from ESLint.
- JavaScript files are ignored where they are not covered by the TypeScript projects.

Files in `public/`, `dist/`, and `node_modules/` are explicitly ignored.

## Related Issues

This configuration keeps ESLint and the application/test type checks aligned without relying on a separate ESLint-only TypeScript project.
